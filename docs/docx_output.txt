AutoSense — Backend & Simulator
Files to build next, and the folder structure to put them in
1. What This Covers
The React frontend is done. This document lists every file the Backend team (FastAPI + PostgreSQL + WebSocket) and the ECU Simulator need to build next, why each file exists, and how the folders should be organized so the frontend's expectations (REST endpoints + WebSocket messages) are met exactly.

5. Contract Between Frontend & Backend
These are the exact shapes the frontend already expects — match them and no frontend code needs to change:
WebSocket ws://<host>/ws/telemetry sends frames like {"type": "reading", "data": {...}}, {"type": "fault", "data": {...}}, and {"type": "fault-clear", "data": {"id": "..."}}
GET /api/telemetry/history?range=1h|24h|7d returns a list of {timestamp, engineTempC, batteryVoltage, rpm}
GET /api/trips returns a list of {tripId, distanceKm, avgSpeedKph, idleMinutes, fuelUsedLiters, startedAt, endedAt}
Field names are camelCase to match the frontend's TypeScript types directly — no renaming needed on either side
6. Suggested Build Order
1. ecu-simulator/simulate.py — get fake data flowing (30 min)
2. app/models + app/database.py + one POST endpoint — save readings to PostgreSQL (1 hr)
3. app/routers/websocket.py + app/services/broadcast.py — push live data to the dashboard (1 hr)
4. app/services/health_score.py + alert_engine.py — compute score, fire faults (45 min)
5. app/routers/telemetry.py history endpoint + app/routers/trips.py — power the charts & trip summary (1 hr)
6. app/services/notifications.py — wire up Twilio SMS (30 min)
7. app/auth/ + app/routers/auth.py — add login if there's time left
